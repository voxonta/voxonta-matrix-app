# Самостоятельный виджет Voxonta

Новый режим включается явно (`WIDGET_ENABLED=true`). Виджет имеет собственный
ключ `voxonta`, URL `/widget/`, интерфейс и серверные настройки. Видеорекордер
не устанавливается, не вызывается и не изменяется этим продуктом.

## Поведение

- Установка виджета не включает транскрибацию. Старт/пауза/продолжение/завершение
  доступны администратору комнаты: PL ≥100, включая создателя комнаты v12.
- Пауза сохраняет встречу. «Завершить» прекращает её; следующий старт создаёт
  новый session_id даже в продолжающемся звонке.
- Панель показывает `starting`, `transcribing`, `stopping`, `paused`, `unknown`.
  `transcribing` появляется после поступления аудио в sink перехватчика; это
  состояние захвата, не подтверждение распознавания или сохранения каждого кадра
  шлюзом. При тишине статус может оставаться `starting`.
- Остановка подтверждается отчётом перехватчика с текущей revision, после
  завершения ранее начатого вызова sink. При отсутствии подтверждения успех не
  показывается. Разрешение захвата истекает через 4 с без обновления; NTP на обоих
  хостах обязателен. Старым перехватчикам widget-встречи не выдаются.
- После команды панель можно закрыть. Команды с request_id, вызовы, аудитория,
  настройки, результаты и публикация сохраняются в Postgres. Два старта дают одну
  встречу. После паузы явно выберите «Продолжить», после завершения — новый старт.
- В комнате нужен установленный виджет с точно совпадающим URL из конфигурации
  адаптера. Вызовы start/stop/settings/result заново проверяют членство и widget.
- Аудитория — участники Matrix-комнаты, как в действующем режиме Talk/Matrix.
  Gateway получает Matrix ID/имена; сшивка с Nextcloud остаётся в Voxonta.
- Участникам доступны только саммари и расшифровка. Все остальные файлы продолжает
  забирать центральный архив Nextcloud. Две выбранные копии виджет хранит в
  `voxonta_widget_artifacts` (BYTEA), metadata — в `voxonta_widget_state` (JSONB).
  ACK этих файлов уходит только на следующем проходе после commit. Наличие
  Matrix-публикации для доступа к этим копиям не требуется. Включите обе таблицы
  в резервное копирование; автоматической очистки локального архива пока нет.
- Автопубликация выключена; настройка личная для комнаты и фиксируется на старте.
  Включение не публикует историю. Ручная кнопка доступна аудитории встречи при
  действующем членстве. Повтор ручной/автоматической публикации не создаёт копию.
- Ссылки ведут на авторизуемый вход в материалы через отдельный виджет. При
  открытии ссылки вне iframe показана кнопка перехода в комнату Element: откройте
  там Voxonta и нужную встречу. Это не публичный файл и не самостоятельный SSO
  вход в браузере. Прямой вход без Element потребует отдельной OIDC-интеграции.

## Конфигурация интеграции

Существующие переменные gateway, LiveKit, Postgres и capture остаются.

```text
WIDGET_ENABLED=true
WIDGET_PUBLIC_URL=https://voxonta.example/widget
WIDGET_PARENT_ORIGINS=https://element.example
WIDGET_SESSION_SECRET=<случайный секрет от 32 символов>
WIDGET_ADAPTER_URL=http://synapse:8008/_synapse/client/voxonta/widget
WIDGET_ADAPTER_TOKEN=<отдельный случайный секрет от 32 символов>
WIDGET_PORT=8082
BOT_MODE_ENABLED=true
```

Parent origins — список разрешённых HTTPS origins через пробел. Браузерный
порт 8082 публикуется только за HTTPS reverse proxy: путь `/widget/` передаётся
без удаления префикса. 8081 остаётся служебным API захвата, 8080 — AS. Не открывать
AS listener или Synapse adapter наружу. Ограничить внутренний путь адаптера
по сети и bearer secret; токены никогда не передаются в iframe.

Для установки только widget-режима задайте `BOT_MODE_ENABLED=false`. Тогда
`MATRIX_AS_TOKEN`/`MATRIX_HS_TOKEN` не требуются и AS listener не запускается.
Старые bot-mode вызовы и незавершённые доставки перед этим должны быть завершены:
сервис откажется стартовать, если они остались в БД. На время миграции режимы
можно держать одновременно в разных комнатах.

Перехватчик должен содержать ветку отчётов `widget-v1`; установить
`POLL_INTERVAL=1`. Бинарник из прежнего релиза 0.3.2 не поддерживает этот протокол.
Один capture worker на инсталляцию; резервный запускается после остановки
предыдущего. Несколько одновременно работающих capture workers не поддерживаются.

## Адаптер Synapse

Скопировать `synapse/voxonta_widget_adapter.py` в каталог модулей. Проверено на
Synapse **1.163.2**; используемые приватные API отправки зафиксированы этой версией.
До обновления Synapse выполнять `tests/synapse_widget_e2e.py` на локальном стенде.

```yaml
modules:
  - module: voxonta_widget_adapter.VoxontaWidgetAdapter
    config:
      token: <тот же секрет, что WIDGET_ADAPTER_TOKEN>
      widget_key: voxonta
      widget_url: https://voxonta.example/widget/?roomId=$matrix_room_id
      auto_install: false
```

`auto_install=true` добавляет отдельный виджет в новые обычные комнаты. В уже
существующие комнаты его устанавливает администратор обычным state-событием
`im.vector.modular.widgets`, state_key `voxonta`, content как ниже. Код адаптера
не меняет power levels, состав комнаты или виджет видеорекордера.

```json
{"id":"voxonta","type":"m.custom","name":"Voxonta","waitForIframeLoad":true,
 "url":"https://voxonta.example/widget/?roomId=$matrix_room_id"}
```

Адаптер читает whitelist метаданных и хранит только sticky RTC, не переписку.
Снимок legacy-состояния читается заново; sticky-события восстанавливаются из
собственной таблицы `voxonta_widget_rtc` после рестарта. Новые события до установки
адаптера восстановить из этой таблицы невозможно: миграция только между звонками.
Native sticky требует включённого MSC4354 на Synapse; legacy не требует его.

Публикация делает обычное Matrix-событие от разрешившего участника. У пользователя
создаётся именованное устройство `voxonta-widget` («Voxonta: публикация результатов»),
без access token. Это нужно для штатной transaction-id дедупликации Synapse.
Таблица `voxonta_widget_delivery` сохраняет event_id. Если после неопределённой
отправки прошло более часа и квитанция не сохранена, адаптер возвращает 409
вместо слепого повтора. Проверить событие по `org.voxonta.meeting`, затем либо
восстановить квитанцию в собственной таблице модуля, либо явно разрешить повтор
после подтверждения отсутствия события. Системные таблицы Synapse не править.
Чужой sender, произвольный текст, ссылки наружу и отправка без widget запрещены.

## HTTP-контракт

- POST `/widget/api/session`: `{room_id, openid}` → bearer UI-сессия на 15 минут.
  Только заранее заданный homeserver; пользовательский URL не используется.
- POST `/widget/api/status`: состояние, can_control, настройки и доступные встречи.
- POST `/widget/api/command`: `{action, request_id, value?}` → 202 после commit.
  action: start/pause/resume/finish/settings/publish/revoke. value для settings — boolean,
  для publish/revoke — session_id. Повтор request_id с другим действием отклоняется.
- POST `/widget/api/result`: `{session_id, kind}` → авторизованный Markdown.
- POST служебного `/apps/voxonta/api/v1/service/capture`: `{reports:[{session_id,
  revision,phase}]}` с service token. Widget-вызовы выдаются только при заголовке
  `X-Voxonta-Capture-Protocol: widget-v1`.
- Внутренний Synapse adapter: snapshot `{room_id}` или publish `{room_id, sender,
  meeting_id, links}`. Доступ только с отдельным adapter token. Соответствие
  meeting/инициатор/согласие хранит и проверяет интеграция, не браузер.

## Выпуск и откат

1. Сохранить БД и старые образы. Установить адаптер через эксплуатацию вне звонков.
2. Выпустить обновлённый capture и интеграцию, widget mode пока выключен.
3. Проверить внутренний adapter и TLS/origin, установить отдельный виджет в
   личную и групповую тестовые комнаты без бота; включить widget mode.
4. Проверить настоящий Element Web и Desktop: OpenID/handshake, права обычного
   участника, ≤3–4 с до захвата при готовом медиа, pause/resume/finish, отзыв,
   перезапуск, закрытие панели, публикацию и архив NC. Element X — вне приёмки:
   произвольные widgets им не поддерживаются.
5. Переводить согласованные комнаты после завершения старых встреч/доставок,
   затем выводить бота только из них. Не включать запись автоматически.

Откат — после завершения/сохранения widget-встреч выключить WIDGET_ENABLED,
вернуть прежние образы и прежний режим выбранных комнат. Новые таблицы оставить:
они аддитивны, их удаление потеряет архив/квитанции. Не приглашать бота массово.

## Локальная проверка

`pytest tests` с `TEST_DATABASE_URL` проверяет сериализацию команд в Postgres,
rollback, сохранение байтов и получение после пересоздания сервиса. CI отдельно
запускает Synapse 1.163.2 по `tests/synapse-widget.yaml` (только тестовые секреты,
открытая регистрация, localhost) и `python3 tests/synapse_widget_e2e.py`.
Это не конфигурация для боевого сервера.


Предпросмотр панели: [desktop](images/widget-desktop.png). Изображение получено
в Chrome с поддельным Widget API; оно не является подтверждением приёмки Element.

Отдельная кнопка отзыва публикации действует на конкретную встречу и не удаляет
архив. Инициатор может отозвать своё разрешение даже после понижения PL, пока
остаётся участником комнаты. Уже отправленное сообщение кнопка не удаляет.
